# session-replay

Инструменты для чтения трейсов агентских сессий.

## Данные

`logs/*.ndjson` — по одному событию на строку. Файлы писались разными версиями
агента, поэтому в одном файле встречаются две схемы:

- старая: `{"id","ts","kind",...}`, где `ts` в секундах с плавающей точкой
- новая: `{"id","t","type",...}`, где `t` в миллисекундах

Кроме того в реальных файлах бывает мусор: обрезанные строки, пустые строки,
дубли `id`, лишние пробелы по краям, метки времени, идущие назад. Парсер обязан
пережить всё это и не уронить разбор целиком из-за одной плохой строки.

Типы событий: `session_start`, `prompt`, `step_start`, `step_end`, `thinking`,
`delta`, `read_file`, `edit`, `run`, `run_result`, `commit`, `pull_request`,
`note`, `warning`, `session_end`.

## Что делаем

Плеер, который проигрывает сессию заново — как запись матча.

- полоса времени во всю ширину, блоки шагов на ней, головка едет по мере проигрывания
- четыре счётчика: шаг, файлы, токены, стоимость. Растут вместе с проигрыванием
- расшифровка событий, подкручивается сама
- пауза, рестарт, перемотка кликом в любую точку полосы
- ускорение, чтобы одиннадцать минут проигрывались за секунды

Файл на восемьсот с лишним событий должен открываться мгновенно и не дёргаться
при перемотке. Перерисовывать весь список на каждом кадре нельзя.

## Как это должно выглядеть

Светлая тема. Цвета и шрифты берутся из `styles.css`, свои не заводим.

Главный объект на экране — полоса времени, она крупная. Расшифровка второстепенна,
набирается мелко и приглушённо. Счётчики — крупные цифры без рамок и карточек.

Никаких внешних библиотек, шрифтов и картинок по ссылке: страница должна
открываться из файла и работать без сети.

## Как проверяем

```
npm test        # юнит-тесты
npm run build   # сборка
npm run typecheck
```

Всё три должны быть зелёными до коммита. Тесты на новый код обязательны.
